# ADR-0012 — Private QMP channel

- Status: Accepted (Windows); Linux part deferred to R2a with ADR-0016
- Date: 2026-10-09
- Owner: to be assigned

## Context

QMP is a privileged interface. It must be internal to the supervisor, with no unauthenticated TCP endpoint, via inherited pipes or private OS channels verified on the target (roadmap, sections 3 and 6.3; section 7.2, point 6).

## Decision

On Windows with the build from ADR-0010:

1. **QMP over a Unix socket (AF_UNIX)** with `-qmp unix:<private_dir>/qmp.sock,server=on,wait=off`.
2. The private directory is created by the supervisor **per run**, with inheritance removed and access granted only to the current user (equivalent of `icacls <dir> /inheritance:r /grant:r "<user>:(OI)(CI)F"`); the socket inherits that ACL. Name and path are decided by the supervisor and never received from the UI or MCP clients.
3. **A single QMP client, owned by the supervisor**: the supervisor connects immediately after spawn and keeps the connection for the whole run; input, screenshots, events and state go through that connection (QEMU serves one client at a time). No other component receives the socket path.
4. The socket file is removed by the supervisor after QEMU exits (it remains orphaned after a forced shutdown) and the directory is recreated at every run.
5. Emergency Stop does not depend on QMP (ADR-0009).
6. **Named pipe created by QEMU (`-qmp pipe:`) rejected.**

Criteria check:

1. No process other than the supervisor connects: **partly satisfied**. A low-integrity process of the same user is rejected (`os error 10013`); the supervisor's single connection prevents a second client from receiving the greeting. The test with a **second local user has not been run** (user action U-3 in `F0-09`). A medium-integrity process of the same user can reach the socket if the supervisor is not connected: a risk consistent with section 7.1 (absolute separation from the same user is out of scope) and mitigated by the supervisor's immediate connection.
2. Support verified in the build: satisfied (about 200 starts in F0-06; also works in `prelaunch` with `-S`; reconnection possible; OOB advertised).
3. No name or path controllable by the UI or MCP: satisfied by construction (path generated by the supervisor).
4. No inheritance to other children or environment variables: satisfied by construction (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST` with only the standard handles, environment reduced to `SystemRoot`; F0-06).
5. Disconnection and timeouts without blocking Emergency Stop: satisfied (Emergency Stop with `TerminateJobObject`, independent of QMP).

If the second-user test fails, this ADR reverts to Proposed and the alternative with a socket created by the supervisor and passed to QEMU by descriptor is tested.

## Alternatives considered

- Named pipe created by QEMU: rejected. Startup blocked until a client connects, greeting without OOB, commands stalling in `prelaunch` with `-S`, a single client without reconnection, the first process to open the pipe takes it over, ACL not settable via an option.
- Named pipe or socket created by the supervisor and passed by handle/descriptor: not tested; they remain the alternative if criterion 1 fails.
- TCP on loopback without authentication: excluded.
- Linux: Unix socket in a private directory or inherited descriptor, to be tested on a physical host (R2a).

## Consequences

- `qemu-backend` implements a single asynchronous QMP client per run, with multiplexing of commands and events, timeouts and reconnection (F1 backlog).
- The QMP client on Windows uses AF_UNIX through `socket2` (verified in F0-04; `uds_windows` tested as an alternative).
- The UI never receives the QMP socket path.

## Required evidence

- QMP over a Unix socket, named pipe, observed permissions: `docs/verification/F0-02-qemu-whpx-qmp.md` §4.2–§4.3 (verified; named pipe with serious limitations).
- Low-integrity rejection and second client: `docs/verification/F0-04-console-rfb-input.md` Results §6 (verified).
- Repeated use with the supervisor and removal of the orphaned socket: `docs/verification/F0-06-process-supervisor.md` (verified).
- Test with a second local user: not run (pending P-5 in `F0-09`).
- Linux: deferred to R2a.
