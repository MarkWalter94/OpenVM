# ADR-0031 — Host/guest integration in manual use: shared folders, clipboard, file drag and drop, USB

- Status: Accepted (2026-10-14); manual-use-only rule replaced by ADR-0034 (2026-10-15)
- Date: 2026-10-14
- Owner: project owner (decision); implementation recorded below

## Context

The project owner requires the integration users know from VMware: shared folders, clipboard copy and paste, drag and drop of files between host and guest, USB devices. The roadmap AI profile (section 7.2) forbids host sharing, clipboard and USB passthrough for AI sessions, and the MVP has no guest agent. VMware Tools cannot work under QEMU (their channel is the VMware backdoor RPC, which QEMU's `vmport` does not implement).

## Decision

**Manual use and agent sessions.** The integration features are off by default and enabled per VM by the user; enabled features are shown on the VM and in the console. In agent sessions each one is a capability granted explicitly (ADR-0034): what is not granted is disconnected before the session starts (shared folders unmapped and their channel closed, clipboard sync stopped, transfers cancelled, USB devices detached; the session is refused if one cannot be disconnected), and what is granted is disconnected on revocation, expiry and Emergency Stop.

**LightVM Tools.** A guest component installed by the user from a data medium generated by LightVM (as VMware Tools). It carries clipboard, file transfer and the shared-folder mapping. It is not the R4a guest agent and gives agents no capability. It must run on every supported guest (Windows XP to 11, Linux): the Windows build cannot use the Rust standard library on Windows before 10, so the Windows tools are written against Win32 directly with a toolchain that targets XP/Vista.

**Channel.** Chosen by a spike among: (a) an isolated user-mode network (`-nic user,restrict=on` with only `guestfwd` to endpoints served by the supervisor: no host, LAN or Internet access; e1000 has inbox drivers on every Windows), (b) `virtio-serial` (needs drivers; recent virtio-win does not cover Vista/XP), (c) an emulated serial port (no drivers, too slow for files). The channel is authenticated per VM and run; guest data is untrusted (sizes, names, paths validated; nothing interpreted as host paths or commands).

**Shared folders.** The user picks host folders in the app (read-only or read-write). They appear in the guest as a drive letter (Windows) or mount (Linux). Candidate on Windows guests: a WebDAV endpoint served by the supervisor on the channel and mapped by the built-in WebDAV redirector (Vista and later), behind the same checks as other host paths (no traversal, links, device or UNC paths, confined to the chosen folder).

**Clipboard.** Text (and images where the guest supports them), both directions, only while the console has focus and the feature is enabled.

**Drag and drop.** Host to guest: files dropped on the console are transferred by the tools into a guest folder (the drop target when the guest supports it, the desktop otherwise). Guest to host: files dragged out of the console are transferred to the host drop target. Size and count limits; progress and cancellation.

**USB.** The user attaches a host USB device to a running VM from the console. Method (owner decision 2026-10-15, after the `R6-04` spike): **`usb-redir` with the UsbDk filter driver** — a redirection helper built on usbredir and libusb with the UsbDk backend captures the device only while it is attached and returns it to the host on detach, as in VMware; QEMU receives it through a `usb-redir` device on a private chardev socket. UsbDk (Red Hat, signed) is installed once by the user with administrator rights, an explicit choice in the app; LightVM never installs drivers silently. `usb-host` with a WinUSB driver bound per device (verified in `R6-04`) is not adopted: the device stays unusable on the host until the original driver is restored. Controller per profile: EHCI for guests without xHCI drivers (XP, Vista, 7), xHCI otherwise.

## Required evidence

- Each feature: off by default, enabled per VM, disconnected before an agent session (negative test: a session cannot start while one cannot be disconnected).
- Channel: no route to host, LAN or Internet from the guest (section 7.4 network tests repeated with the channel enabled).
- Shared folders: traversal, links, junctions and device paths refused; read-only folders not writable from the guest.
- Real guests: Windows Vista, Windows 10/11, Linux. **Not verified.**
