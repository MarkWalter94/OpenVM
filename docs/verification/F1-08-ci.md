### 3. F1-15 — cgroup delegation with D-Bus `StartTransientUnit` (ADR-0015 part A)

**Method.** The supervisor, without launching `systemd-run`, asks the systemd manager **of the user** (session bus, `org.freedesktop.systemd1`, object `/org/freedesktop/systemd1`, interface `org.freedesktop.systemd1.Manager`) to create a transient scope unit containing its own PIDs:

```text
StartTransientUnit(name: s, mode: s, properties: a(sv), aux: a(sa(sv))) -> job: o
  name       = "lightvm-<id>.scope"
  mode       = "fail"
  properties = [ ("PIDs", au [<supervisor pid>, ...]),
                 ("Delegate", b true),
                 ("Description", s "...") ]
  aux        = []
```

Then: wait for the job to finish (`JobRemoved` signal, or reading `/proc/self/cgroup` until it contains the scope); with `Delegate=yes` the scope's directory belongs to the user; move the supervisor into a leaf `supervisor/` (cgroup v2 "no internal processes" rule), create one leaf per VM, enable `+cpu +memory +pids` in `cgroup.subtree_control`, write `memory.max`, `cpu.max`, `pids.max` (ADR-0017), terminate the tree with `cgroup.kill` and wait for `populated 0` in `cgroup.events`. In Rust the D-Bus client can be `zbus` (already in the Linux graph through AccessKit, pure Rust); the choice is left to the supervisor stream.

**Behaviour without a systemd user session** (distributions without systemd, containers, sessions without `user@.service`, some CI runners without linger): the user bus is not reachable (`busctl --user`: `Failed to connect to user scope bus via local transport: No such file or directory`); there is no unprivileged alternative to obtain a writable cgroup subtree (F0-07: `mkdir` in the startup cgroup → `Permission denied`). Consequence already proposed in F0-07 and ADR-0015: fallback to process group + `PR_SET_PDEATHSIG` + pidfd with the declared limit (descendants that change group not contained, no CPU/memory limit on the tree) and **AI Mode disabled** on that host (section 7.2 point 8); the supervisor must report the condition as a missing capability, not as a generic error.

Observation from the first attempt (log not kept, overwritten by the second run): with a single process in the scope, `cgroup.kill` on the VM leaf emptied the whole scope and systemd removed it together with the sub-cgroups (`cgroup.events` no longer existing). **The scope must also contain the supervisor** (or a process that keeps it alive) for the VM's sub-cgroup to survive the VM's termination; the final probe and the CI step do so.

## Limits

- CI never run: no job is verified on the runners.
- cgroup probe only in WSL2 with `sleep`: it does not verify QEMU with KVM, accounting of guest memory, effect of `cpu.max` on vCPU threads (deferred to R2a, ADR-0016).
- YAML validation and actionlint do not verify the semantics of the commands nor the availability of the packages.
- The steps that depend on the `lightvm-desktop` CLI (`--smoke`, `--renderer`, `--wgpu-adapter`) follow the current interface, which another stream is evolving (F1-14, F1-16).
- The process job filters follow the current module names of `qemu-backend` (`sys::windows`, `process`, `storage_guard`), which may change.
